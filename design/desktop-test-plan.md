# Absorb Agent 桌面端功能测试方案（P0）

> 状态：待评审
> 被测对象：分支 `feature/desktop-wails`，`build/bin/absorb-agent-desktop.exe`（0.1.0）
> 依据：[wails-desktop-design.md](wails-desktop-design.md) §6 P0 验收（扩展照常问答 + 状态页正确反映状态）、[desktop-ui-design.md](desktop-ui-design.md) §5/§6/§7
> 核心风险：桌面化改造动了 main.go 启动链路，**最大风险是破坏扩展问答既有链路**——所有用例围绕此展开

---

## 1. 测试分层与策略

| 层 | 方式 | 覆盖内容 |
|---|---|---|
| L1 自动化脚本 | PowerShell 冒烟脚本（可重复执行，进 `scripts/smoke-desktop.ps1`） | /health 特征、心跳注册、端口冲突、进程存活 |
| L2 半自动验证 | PowerShell 直接查数据（配置文件、SQLite、日志） | 配置生成、Key 保留、端口落盘 |
| L3 人工冒烟 | 真机操作 exe + Edge 扩展 | 窗口/托盘/三视图/主题/全链路问答 |

不可自动化边界（沿用 2026-10-04 结论）：Wails WebView 内 UI 交互、托盘菜单、窗口行为（单实例/关窗隐藏）无法脚本驱动，全部走 L3。

## 2. 测试环境准备（每轮回归前重置）

1. 退出桌面端进程；备份或删除数据根 `%APPDATA%\absorb-agent\`（制造首启场景）
2. `edge://extensions` 重载扩展（Edge CSS 磁盘缓存教训）
3. 确认智谱 API Key 可用（一组有效 Key + 一组无效 Key）
4. 构建：前端 `npm run build` → Go 重编（msys64 终端）→ 确认 exe 时间戳晚于源码

## 3. 用例明细

### A. 启动与生命周期（L3 人工，6 例）

| # | 前置 | 步骤 | 预期 |
|---|---|---|---|
| A1 | 数据根已删 | 双击 exe | 窗口打开显示状态页；`%APPDATA%\absorb-agent\` 自动生成：`config/config.yaml`（Key 空、0600）、`config/glm-system.md`、`data/`（两个 SQLite）；状态页模型卡=琥珀"未配置" |
| A2 | 应用已运行 | 再次双击 exe | 不出现第二个窗口/进程，已有窗口被唤起 |
| A3 | 应用已运行 | 点窗口 X | 窗口消失但进程存活；`/health` 仍 200；托盘图标在 |
| A4 | 窗口已隐藏 | 托盘菜单"显示主窗口" / "退出" | 前者唤起窗口；后者进程退出、`/health` 不通 |
| A5 | exe 旁新建 `data\` 空目录 | 启动 | 进入便携模式：config/data 全部生成在 exe 旁 |
| A6 | 正常运行 ≥2 分钟 | 观察状态页服务卡 | 绿点"运行中"，运行时长合理（非 0 或负） |

### B. HTTP 桥与扩展连接（L1 脚本 + L3，5 例）

| # | 前置 | 步骤 | 预期 |
|---|---|---|---|
| B1 | 应用运行 | `curl http://localhost:7788/health` | 200，JSON 含 `"service":"absorb-agent"`、`"ok":true`（特征字段齐全） |
| B2 | 扩展已加载、浏览器打开 | 打开 Edge 任意页，等 ≤1 分钟；看状态页扩展卡 | "已连接"（心跳自动报到，零配置） |
| B3 | 曾连接过 | 关闭浏览器 >3 分钟 | 扩展卡变"连接断开"（灰点，提示确认浏览器已打开）；重开浏览器后 5s 轮询内恢复 |
| B4 | 7788 被其他程序占用（`python -m http.server 7788` 模拟） | 启动 exe | 进程不崩；服务卡红点+人话"通信端口被占用"；排除占用后重启恢复 |
| B5 | Key 已配置、扩展已连接 | **划词→右键"针对此句提问"→面板提问** | SSE 流式回答正常——P0 核心用例，桌面化不得影响原链路 |

### C. 状态页（L3 人工，4 例）

| # | 步骤 | 预期 |
|---|---|---|
| C1 | Key 留空时看模型卡 | 琥珀点"还没有配置模型"+ [去设置] 跳转设置页 |
| C2 | 填 Key 保存并重启 | 模型卡绿点"已就绪"+ 模型名 |
| C3 | 数据卡按钮 | [打开数据文件夹]/[打开日志文件夹] 分别落到 `%APPDATA%\absorb-agent\data\` 与 `data\logs\` |
| C4 | 会话数核对 | 数据卡会话数 = 会话页实际条数 |

### D. 会话管理（L3 人工 + L2 数据核对，4 例）

| # | 前置 | 步骤 | 预期 |
|---|---|---|---|
| D1 | 扩展造 2-3 个会话（不同页面划词提问+追问） | 打开会话页 | 倒序排列；标题=首问截断；每条"对话数/划词数"与实际一致 |
| D2 | 点任一会话 | 查看详情 | 用户消息=纯问题（无 `<reference_material>` 标签残留）；助手回答 markdown 正常（标题/代码块/列表）；标题/域名等元数据不混入正文 |
| D3 | 点删除某会话 | 确认层出现→确认 | 列表移除；**重启 exe 后仍不存在**（DB 落盘）；L2：sqlite 查 session 表该行已删 |
| D4 | 删除全部会话 | 查看列表 | 空态文案+引导正常 |

### E. 设置（L3 + L2，5 例）

| # | 步骤 | 预期 |
|---|---|---|
| E1 | 输入 Key → 保存 → 重启 | config.yaml `api_key` 已更新且文件权限 0600；重启后模型卡"已就绪" |
| E2 | **Key 留空 → 保存** | 原 Key 保留不被清空（防误清）；L2 查 yaml 确认 |
| E3 | 眼睛图标切换 | Key 明文/密文切换正常，默认密文 |
| E4 | 关闭记忆开关 → 保存 → 重启 → 扩展提问 | 启动日志无"画像蒸馏器已启动"（记忆服务未装配）；回答正常 |
| E5 | 通信端口改 7789 → 保存 → 重启 | 保存时提示需重启；重启后 `/health` 在 7789 响应；扩展端需同步改地址（提示文案已含此说明） |

### F. 主题（L3，2 例）

| # | 步骤 | 预期 |
|---|---|---|
| F1 | 顶栏月亮按钮切换亮/暗 | 即时生效且全视图协调（无白底黑块残留）；重启 exe 后保持上次选择 |
| F2 | Windows 系统切暗色 → 首次启动（无 localStorage） | 应用直接进暗色 |

### G. CLI 模式回归（L1 + L3，2 例）

| # | 步骤 | 预期 |
|---|---|---|
| G1 | `absorb-agent-desktop.exe -cli` 启动 | 控制台日志正常起服务；`/health` 200；无窗口弹出 |
| G2 | CLI 运行时扩展划词提问 | 回答正常（CLI 与桌面共享数据根，互不破坏会话库） |

## 4. 自动化脚本范围（L1，本次测试固化产出）

`scripts/smoke-desktop.ps1` 覆盖（可无 Key 跑）：B1 特征校验、B2 心跳模拟（curl 带 `X-Absorb-Ext: 0.1.0` 头后状态页应判定已连接——需人工看 UI 或读日志）、A3 进程存活、B4 端口占用降级、G1 CLI 起服务。脚本输出 PASS/FAIL 汇总，作为后续回归基线。

## 5. 已知差距（测试时跳过或标注，非遗漏）

- 未保存离开提示（设计 §7 要求，本版未实现）→ E 组跳过
- 引导向导 / 网页抓取增强状态行 / 记忆条数 → 状态页不含这些元素
- 窗口位置记忆 → A 组不做
