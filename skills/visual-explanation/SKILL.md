# Visual Explanation（可视化解释）DSL v1

把复杂解释组织成 `:::absorb-visual` 包裹的页面，面板会渲染成结构化可视化。
**LLM 只负责内容与结构**：不写 HTML/CSS/SVG，图表用 ```mermaid，其余全是 Markdown。

完整契约见扩展侧 `extension/sidepanel/js/visual/SPEC.md`，两者不一致时以 SPEC.md 为准。

## 触发白名单（严格）

| 场景 | 输出方式 |
| --- | --- |
| 术语解释、单点疑问、简单问答 | 普通 Markdown，**禁止**使用本 DSL |
| ≥3 个关联概念构成的结构/机制 | 本 DSL |
| 多步骤流程（协议握手、请求链路、生命周期） | 本 DSL |
| 交互时序、状态机 | 本 DSL |
| 多维度对比（≥3 维或 ≥3 个对象） | 本 DSL |
| 数量对比（耗时/占比/指标等带数字的比较） | 本 DSL（```chart bar） |
| 用户明确要求画图/图示化 | 本 DSL |

## 语法红线

1. 外层容器固定 `:::absorb-visual`（3 冒号）开、单独一行 `:::`（3 冒号）闭。
   **只要页面里出现任何组件或 mermaid 图，就必须先开容器**——组件写在容器外会被当普通
   代码块，等于失效（线上真实故障：整篇没有容器，只有一段 ```tree，用户看到的是代码块）。
2. 组件优先用**围栏写法**：`` ```callout `` 开、`` ``` `` 闭（与 mermaid 同一写法，最不容易错）。
   开行必须**紧跟组件名**：`` ```kv ``。*不能*把组件名写到下一行（`` ``` `` 换行再写 `kv`，
   会被当成普通代码块，组件直接失效）。
   冒号写法 `:::callout` … `:::`（或 `::::`）也兼容，按组件名识别，冒号数不必数准。
3. 全文都是 Markdown；图表只用 ```mermaid 代码块内嵌（flowchart/sequenceDiagram/stateDiagram-v2/classDiagram/erDiagram 五种）。
4. frontmatter 只支持 `template`（sheet|doc）、`title`、`subtitle` 三个键，`---` 成对出现。
5. `## 标题` 切分面板，一个面板只回答一个子问题；`##` 之前的内容是页面导语（2-3 句核心结论）。
6. 每个面板 80-150 字正文 + 至多一个图表/组件；页面总面板数 2-5 个。

## 页面骨架（sheet 模板，最常用）

    :::absorb-visual
    ---
    template: sheet
    title: TCP 三次握手
    subtitle: 可靠连接如何建立
    ---

    导语：三次握手让双方确认收发能力并同步初始序列号，缺一不可。

    ## 握手过程

    ```mermaid
    sequenceDiagram
        participant C as 客户端
        participant S as 服务端
        C->>S: SYN
        S-->>C: SYN+ACK
        C->>S: ACK
    ```

    ## 关键状态

    ```timeline
    - SYN_SENT：客户端发出 SYN，等待确认
    - SYN_RCVD：服务端收到 SYN 并回应
    - ESTABLISHED：双方确认完成，连接建立
    ```

    ```callout tip
    **为什么不是两次**：只有两次无法让服务端确认自己的发送能力可达。
    ```

    :::

## 组件速查

### callout — 提示框（variant：tip / warn / info，默认 info）

    ```callout warn
    **注意**：半开连接会占用服务端资源。
    ```

### kv — 键值对（每行 `key :: value`，值可多行续写）

    ```kv
    平均查询复杂度 :: O(log n)
    实现方式 :: 有序链表 + 多级稀疏索引
    对比对象 :: 红黑树、B+ 树
    ```

### timeline — 时序/步骤（每行 `- 标签：描述`）

    ```timeline
    - SYN：客户端发起，携带初始序列号
    - SYN+ACK：服务端确认并反向同步
    ```

### tree — 层级结构（2 空格缩进一层）

    ```tree
    - 跳表
      - Level 2 稀疏索引
      - Level 1 底层有序链表
    - 哈希表
    ```

### chart bar — 条形数量对比（数值行 `名称 :: 数字`，首部可选 title/unit 元信息）

    ```chart bar
    title: 构建耗时对比
    unit: 秒
    Go :: 4.2
    Rust :: 1.1
    Java :: 12.8
    ```

- 数值必须是纯数字（可带小数），禁止单位写在数值里（`4.2秒` ✗，单位放 `unit:`）。
- 条形宽度按最大值归一，自动渲染，不写任何样式/百分比。
- 适合 2-8 个条目的数量对比；类别型占比（各部分和为整体）同样用它，从大到小排序。

### 对比 — 直接写 Markdown 表格（无需组件，自动获得对比样式）

    | 维度 | 跳表 | 红黑树 |
    | --- | --- | --- |
    | 实现复杂度 | 低 | 高 |
    | 范围查询 | 天然有序支持 | 需中序遍历 |

## 问题类型 → 组件决策表

先判断问题属于哪一类，再按下表选组件；一个页面可以混合两类，但主类型决定导语之后的第一个面板。

| 问题类型（判断信号） | 面板组织 | 首选 | 备选 | 避免 |
| --- | --- | --- | --- | --- |
| 结构/机制（≥3 概念如何配合，"为什么用 X"） | 概念关系图 → 结构拆解 → 机制要点 | flowchart | tree + kv | 单图塞全部概念 |
| 多步骤流程（握手、请求链路、生命周期） | 总流程图 → 关键阶段详解 | flowchart + timeline | kv 补参数 | 纯文字列步骤 |
| 交互时序（协议消息、多方往返） | 时序图 → 容易出错的环节 | sequenceDiagram | — | **把时序画成 flowchart** |
| 状态机/生命周期 | 状态图 → 状态推进对照 | stateDiagram-v2 + timeline | — | 两张图重复表达同一组状态 |
| 多维对比（≥3 维或 ≥3 对象） | 对比表 → 选择建议 | Markdown 表格 + callout | kv | **用 flowchart 画对比** |
| 层级/分类（组成、包含关系） | 层级树 → 各层说明 | tree | flowchart | 列表平铺无层级 |
| 演化/历史（版本演进、阶段发展） | 时间线 → 里程碑 | timeline | 表格 | tree（时间不是层级） |
| 数值对比（"哪个更快/更省"、耗时、占比、指标） | 条形图 → 一句结论 | chart bar | Markdown 表格（维度多时） | **把数字写成流水句**；数值带单位 |
| 用户明确要求图示化 | 按内容匹配上表；无明确类型时 flowchart 概览 + callout 结论 | — | — | 不判断类型随意配图 |

## 组合规则

1. 一张图回答一个问题；同一信息禁止用两种组件重复表达（如 stateDiagram 又配 timeline 讲同一组状态——timeline 只做状态与动作的对照，不重复画转移）。
2. 首选列内"+"表示两个组件各占一个面板，不是塞进同一面板。
3. 表格维度 ≤4 数据列（首列为维度名）；超出的维度拆成第二个面板的补充表。
4. 页面图表 ≤3 个（语法红线既有要求）；正文字数红线不变。

## 常见错误（每次输出前自查）

- 时序问题画成 flowchart（箭头无方向语义、消息丢失）→ 必须 sequenceDiagram。
- 对比问题画成 flowchart（分支表达不了多维属性）→ 必须表格。
- 数值写进条目文字（`Go：4.2秒`）而不是 chart → 带数字的对比用 ```chart bar。
- chart 数据行漏 ` :: ` 或数值带单位 → 该行被丢弃不渲染，务必每行 `名称 :: 纯数字`。
- 单面板堆 2 个以上组件 → 拆面板。
- 回答里画了组件却没开容器 → 组件全部变成代码块；**先写 `:::absorb-visual` 再写内容**。
- 全页面全是图没有文字 → 每面板 80-150 字正文是硬要求。
