Absorb 阅读助手 浏览器扩展隐私政策

生效日期：2026-11-16 ｜ 最近更新：2026-11-16 ｜ 适用于：Absorb 阅读助手浏览器扩展（Chrome / Edge，Manifest V3）

一句话摘要：本扩展不会把任何数据发送给我们或任何第三方服务器。你划选的文字、网页内容、截图与提问，只通过 localhost 传给你在自己电脑上安装的 Absorb 桌面应用，并由桌面应用发送至你自行配置并持有密钥的 AI 服务商以生成回答。本扩展不含任何统计、分析或追踪代码。

一、我们处理哪些数据

本扩展是"触发式"工作的：只有当你主动划词提问、点击解读按钮或截图时，才会读取当次操作所需的数据。没有用户操作时，不采集任何内容。

截图与图片区域 / 元素 / 视口截图，或你主动上传、粘贴的图片使用图片提问功能
对话内容你的提问与 AI 回答、会话列表、未发送的草稿使用对话功能
扩展设置界面偏好等本地设置项使用扩展时

二、数据流向与存储

  • 扩展自身只访问本机。所有网络请求仅指向 http://localhost / http://127.0.0.1 上的本地桌面应用桥接服务。扩展内不存在任何指向外部服务器的请求。
  • AI 处理由桌面应用完成。桌面应用把提问与页面内容发送给你在桌面端自行配置的 AI 服务商（使用你自己的 API Key），用于生成回答。该环节受对应服务商隐私政策约束，本扩展不参与、不中转、不缓存。
  • 本地存储。会话记录、知识草稿由桌面应用保存在你电脑的数据目录；扩展的草稿、待发送划词队列、文档卡片与设置保存在浏览器 chrome.storage.local 中。以上数据均不出本机。
  • 桌面应用版本检查。桌面应用可能访问其发布服务器获取新版本号，该请求不含你的任何使用数据。

三、我们不做什么

  • 不收集、不出售、不出租、不与任何第三方共享你的数据（AI 服务商除外——那是你自己的配置）。
  • 不含广告、埋点、崩溃上报、行为追踪。
  • 不在后台扫描或预读你的浏览记录；对网页的读取仅在你在当前页面主动触发功能时发生。
  • 不将数据用于机器学习训练或与核心功能无关的用途。

五、第三方服务

本扩展自身不调用任何第三方服务。AI 能力由桌面应用按你的配置调用对应服务商（如智谱、DeepSeek、Kimi、OpenAI 兼容端点等），提交的内容与密钥直接发生在桌面应用与该服务商之间。

六、数据删除

  • 卸载扩展即删除浏览器侧全部本地数据（草稿、队列、设置）。
  • 桌面应用侧的会话与知识数据保存在本机数据目录，可在桌面应用中删除，或直接删除数据目录。

七、儿童隐私

本扩展面向一般用户，不面向 14 岁以下儿童营销，不有意收集儿童个人信息。

Absorb Reading Assistant — Privacy Policy (Browser Extension)

Effective: 2026-11-16 ｜ Last updated: 2026-11-16 ｜ Applies to: Absorb Reading Assistant extension (Chrome / Edge, Manifest V3)

Summary: This extension never sends data to us or to any third-party server. Selected text, page content, screenshots, and your questions go only to the Absorb desktop application installed on your own computer via localhost. The desktop app then sends prompts to the AI provider you configure yourself (with your own API key) to generate answers. The extension contains no analytics, tracking, or telemetry of any kind.

1. Data We Process

The extension is fully user-triggered. It reads only the data required by the action you take, and collects nothing in the background.

DataDetailsTrigger
Selected textText you highlight on a pageSelection-based question
Page contextURL, title, and main-content text of the page you are readingQuestion / full-page interpret
Screenshots & imagesRegion / element / viewport screenshots, or images you upload or pasteImage-based questions
ConversationYour questions, AI answers, session list, unsent draftsChat usage
SettingsLocal UI preferencesExtension usage

2. Data Flow & Storage

  • The extension only talks to your machine. All network requests go exclusively to http://localhost / http://127.0.0.1, where the companion desktop app listens. The extension makes no requests to any external server.
  • AI processing happens in the desktop app. The desktop app sends prompts to the AI provider you configure (with your own API key). That step is governed by the provider's privacy policy; the extension is not involved.
  • Local storage. Sessions and knowledge drafts are stored on disk by the desktop app; drafts, pending selections, document cards, and settings are stored in the browser via chrome.storage.local. Nothing leaves your machine from storage.
  • Desktop update check. The desktop app may query its release server for a newer version number; this request carries none of your usage data.

3. What We Do Not Do

  • We do not collect, sell, rent, or share your data with any third party (other than the AI provider you configured yourself).
  • No ads, no telemetry, no crash reporting, no behavioral tracking.
  • No background scanning of browsing history; page access happens only when you trigger a feature on that page.
  • No use of data for model training or any purpose unrelated to the core features.

4. Permissions

  • contextMenus — right-click menu entry to start an interpretation.
  • sidePanel — hosts the chat side panel UI.
  • storage — local drafts, pending-selection queue, settings.
  • activeTab + scripting — injects the capture/reading script into the current page only after you trigger it.
  • Host permission <all_urls> — the core feature (select-to-ask and full-page interpretation) must work on any web page you are reading. Scripts are injected only on user action on the current page; no background collection.
  • tabs — reads the active tab's URL/title to build question context and detect PDF pages.
  • clipboardWrite — one-click copy of answers.
  • alarms — connection heartbeat with the desktop app and retry of pending selections.
  • nativeMessaging — communicates with the local Absorb desktop native host (answer generation is done locally).
  • Host permissions http://localhost/*, http://127.0.0.1/* — communicate with the local bridge service of the desktop app.

5. Third-Party Services

The extension itself calls no third-party services. AI capability is invoked by the desktop app per your configuration (e.g., Zhipu, DeepSeek, Kimi, OpenAI-compatible endpoints); content and keys flow directly between the desktop app and that provider.

6. Data Deletion

  • Uninstalling the extension removes all browser-side local data (drafts, queue, settings).
  • Desktop-side sessions and knowledge data live in a local data directory and can be deleted in the app or by removing the directory.

7. Children's Privacy

Not directed at children under 14; no knowing collection of children's personal information.
